The **`did:web`** method is a decentralized identifier ([[DID]]) method designed to leverage the existing web infrastructure. It enables domain name owners to create and manage decentralized identities using standard web technologies like HTTPS. A **`did:web`** DID is created from a domain name and resolves to a [[DID Document]] that is publicly accessible through a URL on that domain.

1. **Web-native**: This method uses familiar web architecture. The DID Document is typically located at a well-known URL (`https://<domain>/.well-known/did.json`), making it easy to set up and use for developers already familiar with the web.
2. **Non-blockchain**: Unlike other DID methods that rely on blockchains, `did:web` simply uses the domain's server to host and serve the DID Document. This makes it cost-effective and free from blockchain-specific scalability or transaction costs.
3. **Interoperable**: It works well with existing internet infrastructure, making it compatible with a wide variety of decentralized identity systems.
4. **Centralization Risks**: While `did:web` is decentralized at the identity level, it relies on the Domain Name System (DNS) and TLS certificates, which are centralized systems. This introduces potential points of control or failure, like domain ownership or certificate management.

[[Resolving a DID]] `did:web`, the identifier is converted into an HTTPS URL, and the [[DID Document]] is retrieved from that address. This method is best suited for web-native applications or organizations looking to integrate decentralized identifiers without the need for blockchain technology. **However, due to its reliance on the DNS and centralized authorities for domain management, it may not be ideal for use cases requiring full decentralization.**
